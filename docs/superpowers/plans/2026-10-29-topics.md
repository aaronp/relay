# Topics Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A SpacetimeDB module plus a Bun-built TypeScript client library and `chat` CLI. Groups and topics are created and accessed by matching kerits policy SAIDs in OIDC JWTs.

**Architecture:** The module is TypeScript and runs on SpacetimeDB 2.12. Reducers do every write and route through one `authorize()` function that reads JWT claims. Reads go through a per-sender view that joins `session` (claims captured at connect) to `topic` to `message`. A repeating scheduled reducer removes expired sessions and topics. The client library wraps generated bindings and is browser-safe. The CLI adds PKCE login and a file-backed config. Local testing swaps the issuer for a Bun dev issuer.

**Tech Stack:** SpacetimeDB 2.12 (CLI + `spacetimedb` npm 2.12.*), Bun 1.3.x (workspaces, `bun test`, `bun build`), `@noble/hashes` (SHA-256 in the module), WebCrypto (dev issuer ES256), `node:util` `parseArgs` (CLI).

**Spec:** `docs/superpowers/specs/2026-10-29-topics-design.md`

## Global Constraints

- SpacetimeDB CLI 2.12.0. The module depends on `spacetimedb` `2.12.*`, as the template generates it.
- Server module language: TypeScript. Everything else: TypeScript on Bun.
- Production issuer `https://oauth.kerits.id`: ES256, JWKS at `/jwks`, auth-code + PKCE S256, no client secret.
- CLI `client_id = http://127.0.0.1:<port>`, `redirect_uri = http://127.0.0.1:<port>/callback`, **fixed port** (default `7863`, override with `--port` / `TOPICS_AUTH_PORT`). Use `127.0.0.1`, never `localhost`.
- Policy claim default key: `kerits.policySAIDs`. Accept the literal flat key first, then the nested path `kerits` → `policySAIDs`.
- Permission lists are any-of matches over opaque SAID strings. The owner (`sub` equals the owner) is always allowed on their own group or topic. *(Spec left this to the builder. The plan decides yes, so authors can't lock themselves out.)*
- Envelope: `{ id, group, topic, sentAt, sender, digest, payload }`. The server sets `sentAt`, `sender` (JWT `sub`) and `digest` (SHA-256, lowercase hex of the payload bytes).
- Max payload is 65536 bytes. Empty payloads are allowed.
- Group and topic names match `^[a-z0-9][a-z0-9_-]{0,63}$`, so the address `group.topic` is unambiguous.
- Sweep interval: 15 s.
- The client library core must not import `fs`, `process`, `Bun` or `node:*`.
- `aud` is not checked. Issuer is checked against `config.trustedIssuer`.

## Review Focus

1. **Token with the policy claim missing, or not a string array:** treat it as having no policies. The user gets a "requires one of [...]" denial, not a module panic. Test: Task 1 `readPolicySaids` cases.
2. **Name containing `.` or uppercase or empty:** rejected at `create_group` / `create_topic` with a clear message. Test: Task 3 `rejects bad names`.
3. **Payload of 65537 bytes:** rejected with "payload too large"; 0 bytes is accepted. Test: Task 3 `payload size limits`.
4. **Sending to a topic that expired and was swept:** `send` fails with "no such topic example.foo". Test: Task 4 `send after topic expiry`.
5. **CLI run with a stored token that is already expired:** the CLI exits non-zero with `token expired — run "chat auth"` instead of hanging on connect. Test: Task 6 `expired token message`.

### Task 3: Groups, topics, send (writes via `authorize`)

**Files:**
- Modify: `module/src/index.ts`, `client/src/index.ts`, `client/src/bindings/*` (regenerate)
- Create: `e2e/writes.test.ts`

**Interfaces:**
- Consumes: Task 1 helpers; Task 2 `config`, `session`, `connect`, harness.
- Produces (module):
  - Table `group` (public): `name: string pk`, `owner: string`, `createTopicPolicies: string[]`, `createdAt: timestamp`.
  - Table `topic` (public): `id: u64 pk autoInc`, `address: string unique` (`group.topic`), `groupName: string index`, `name: string`, `owner: string`, `readPolicies: string[]`, `writePolicies: string[]`, `createdAt: timestamp`, `expiresAt: option<timestamp>`.
  - Table `message` (private): `id: u64 pk autoInc`, `topicId: u64 index`, `group: string`, `topic: string`, `sentAt: timestamp`, `sender: string`, `digest: string`, `payload: u8[]`.
  - `authorize(ctx, action: 'create_group' | 'create_topic' | 'send' | 'read', target: { required: string[]; owner?: string }): { sub: string; saids: string[] }`
    - Reads the JWT from `ctx.senderAuth.jwt`, re-checks `iss` and `exp`, and reads the SAIDs with `readPolicySaids`.
    - Passes when `sub === owner` or `satisfies(...)`. Otherwise it throws `SenderError(missingMessage(action, required))`.
    - Add a `// ponytail:` comment marking it as the insertion point for rate limits and quotas.
  - Reducers:
    - `create_group(name, createTopicPolicies: string[])` requires `[config.createGroupPolicy]`.
    - `create_topic(group, name, readPolicies: string[], writePolicies: string[], lifetimeSecs: option<u64>)` requires `group.createTopicPolicies` with the group owner allowed.
    - `send(address, payload: u8[])` requires `topic.writePolicies` with the topic owner allowed. It enforces the 65536 limit and sets `digest = bytesToHex(sha256(Uint8Array.from(payload)))`.
  - Errors:
    - `invalid name "<n>"`
    - `group "<n>" already exists`
    - `topic "<addr>" already exists`
    - `no such group <n>`
    - `no such topic <addr>`
    - `payload too large (<n> > 65536 bytes)`
- Produces (client):
  - `Client.createGroup(name: string, opts: { createTopicPolicies: string[] }): Promise<void>`
  - `Client.createTopic(addr: string, opts: { readPolicies: string[]; writePolicies: string[]; lifetimeSecs?: number }): Promise<void>`
  - `Client.send(addr: string, payload: Uint8Array): Promise<void>`
  - `Client.listTopics(group: string): Promise<TopicInfo[]>`, where `TopicInfo = { address; name; group; owner; readPolicies: string[]; writePolicies: string[]; expiresAt?: Date }`. It does a one-shot subscription to `SELECT * FROM topic WHERE group_name = '<g>'` and unsubscribes after `onApplied`. Check the column's SQL name in the generated bindings.
  - All of these reject with the server's error message. Check the SDK's reducer-call promise/callback shape in the generated bindings.

### Task 4: Reads (view), pull/watch, sweep, expiry

**Files:**
- Modify: `module/src/index.ts`, `client/src/index.ts`, bindings
- Create: `e2e/reads.test.ts`

**Interfaces:**
- Consumes: Tasks 2–3.
- Produces (module):
  - View `topic_messages` (per-sender `spacetimedb.view`, parameter `{ address: t.string() }`, returns `t.array(message.rowType)`).
    - It finds the topic by address and the caller's `session` by `ctx.sender`.
    - It returns `[]` when either is missing, or unless `session.subject === topic.owner || satisfies(session.policySaids, topic.readPolicies)`.
    - Otherwise it returns `[...ctx.db.message.topicId.filter(topic.id)]`.
    - *Fallback if parameterised per-sender views don't work in 2.12:* a no-param view `my_messages` over all readable topics, with clients subscribing to `SELECT * FROM my_messages WHERE topic_id = <id>`. Note the choice in a code comment.
    - Add `// ponytail: view recomputes the whole topic on every change. Fine for chat-sized topics; switch to a query-builder semijoin if topics get large.`
  - Table `sweep_timer` (scheduled, `ScheduleAt.interval(15_000_000n)`, inserted in `init`) → reducer `sweep`.
    - It deletes sessions with `expiresAt <= ctx.timestamp`.
    - It deletes topics with `expiresAt <= ctx.timestamp` along with all their messages (via the `topicId` index).
  - `create_topic` sets `expiresAt = ctx.timestamp + lifetimeSecs` when it is given.
- Produces (client):
  - `Envelope = { id: bigint; group: string; topic: string; sentAt: Date; sender: string; digest: string; payload: Uint8Array }`
  - `Client.pull(addr: string, opts?: { afterId?: bigint; limit?: number }): Promise<Envelope[]>`
    - Subscribes `SELECT * FROM topic_messages('<addr>')` (escape `'`), takes the rows at `onApplied`, unsubscribes, filters out ids ≤ `afterId`, sorts by id and slices to `limit`.
    - Add `// ponytail: paging is client-side over the subscribed set; add server-side paging if topics get large.`
  - `Client.watch(addr: string, onMessage: (e: Envelope) => void): () => void`. Delivers existing messages first, then each insert. The returned function unsubscribes.
  - Expiry in `connect`:
    - New option `onExpired?: () => Promise<string | undefined>`.
    - At `decodeExp(token)` the client closes the connection and calls `onExpired`.
    - If `onExpired` returns a token, the client reconnects with it and re-establishes every active `watch`.
    - Otherwise it emits a terminal state: `Client.closed: Promise<'expired' | 'closed'>`.

### Task 6: `chat` CLI, auth, README

**Files:**
- Create: `cli/package.json`, `cli/src/main.ts`, `cli/src/args.ts`, `cli/src/args.test.ts`, `cli/src/config.ts`, `cli/src/auth.ts`, `e2e/cli.test.ts`, `README.md`

**Interfaces:**
- Consumes: `@topics/client` (workspace dep), `decodeExp`.
- Produces:
  - `parsePermissions(json: string, keys: string[]): Record<string, string[]>`. Accepts strict JSON whose values are a string or a string array. Unknown keys throw `unknown permission "<k>" (expected one of ...)`. Keys: `create-topic-policy` (group), `read-policy`, `write-policy` (topic).
  - `parseLifetime(s: string): number`. Converts `30s|15m|12h|7d` to seconds and throws on anything else.
  - `parseTopicAddr(s: string): string`. Validates `group.topic` with the same name rule.
  - Config file `~/.config/topics-chat/config.json`, mode 0600, holding `{ server, db, issuer, port, idToken, refreshToken }`.
    - Precedence: flag > env (`TOPICS_SERVER`, `TOPICS_DB`, `TOPICS_ISSUER`, `TOPICS_AUTH_PORT`, `TOPICS_TOKEN`) > file > defaults.
    - Defaults: `server = 'wss://maincloud.spacetimedb.com'`, `db = 'topics'`, `issuer = 'https://oauth.kerits.id'`, `port = 7863`.
    - `TOPICS_TOKEN` overrides the stored token. Tests and scripts use it.
  - `login(cfg): Promise<{ idToken: string; refreshToken?: string }>`
    - Discovers the endpoints from `<issuer>/.well-known/openid-configuration`.
    - Generates a PKCE S256 verifier/challenge and a `state`.
    - Runs `Bun.serve({ hostname: '127.0.0.1', port })`, opens the browser (`open` / `xdg-open` / `start`) and prints the URL as a fallback.
    - Scope `openid`, `client_id = http://127.0.0.1:<port>`.
    - Exchanges the code at the token endpoint and checks `state`.
    - Uses `id_token` unless the manual check in Step 7 shows the SAIDs only arrive on `access_token`. In that case use `access_token` and note it in the README.
  - `refresh(cfg): Promise<string | undefined>`. Runs the refresh-token grant with the same `client_id`.
  - Commands, matching the spec:
    - `auth`
    - `group create --name --permissions`
    - `topic create --name --group --permissions [--lifetime]`
    - `topic list --group`
    - `send --topic -m <text> | --file <path>`
    - `pull --topic [--watch] [--json]`
  - `pull` prints one line per message: `<ISO sentAt> <sender> <payload as UTF-8, or base64 if invalid UTF-8>`. `--json` prints Envelope JSON lines, with the payload in base64.
  - Before connecting, if `decodeExp(token) <= now`, try `refresh`. If there is no new token, print `token expired — run "chat auth"` and exit with code 1. `--watch` passes `onExpired: () => refresh(cfg)`.
  - Errors print the server message to stderr and exit with code 1.
